The     name is composed of the letter "D" followed by the name of the     processor. For example, DZ80 for the processor Z80.        The CALM disassembler generates from a binary file (*.BIN) a source     file (*.ASM) or a listing file (*.LST). The command line looks like     this (for example for the I8051):             DI8051 binary_file [/L]             A listing is generated with /L. The CALM disassembler requires     then:             1) the start address (of the program to disassemble)        2) the processor (if there are more than one, e.g. I8051, I8052 or           S80515)        3) the working mode:           a) disassemble all in one pass (like a debugger)           b) disassemble all in two passes           c) detect in two passes program and data areas             In mode 3a, no labels or assignments are generated. In the other     working modes, the disassembler reads the input file twice. In the     second pass, the source or the listing file is generated. The     disassembler generates labels and assignments. The assignments, the     labels of the variables and some addresses are at the end of the     output file. You must transfer these labels and assignments from the     end to the beginning of the disassembled program to obtain the same     result when reassembling.        Some remarks about mode 3c: When the disassembler should detect     program and data areas, then the program must start with a program     area. The idea is simple: the disassembler simulates the processor and     recognizes so the program areas. However, the diassembler cannot     recognize program areas which are accessed by jump tables. Therefore,     you should use all working modes.        The CALM disassembler defines the data areas, e.g. shows the     variable (read/write) or tables areas (read/in the program area). The     CALM disassembler distinguishes also the constants (displacement, bit,     value, etc.). The disassembler differentiate 6 symbol types: address     (A_xx), bit (B_xx), value (I_xx), offset (O_xx), table (T_xx) and     variable (V_xx).        If the program to diassemble is very complex, it is possible that     the same value is defined more than once (e.g. I_0D = 16'0D). This     means that the value is not always used in same manner. Furthermore,     some symbols are not defined. This is possible with labels/assignments     because the value is within an instruction. Also the message "New     symbol in 2nd pass" may appear.        Example: the program TERMINAL.ASM for the i8080, operating system     CP/M-80.
